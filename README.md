# Wortilo

Многоязычный переводчик и карточки для возвращения к словам, которые встречаются каждый день. Приложение находится на этапе подготовки; этот репозиторий пока содержит проектные skills, а не реализацию продукта.

## Роли Codex

[AGENTS.md](AGENTS.md) — общие инструкции для работы в репозитории: с чего начать, какую роль выбрать, как учитывать учебный режим и чем подтверждать результат. Skills ниже содержат подробные процессы отдельных ролей. Эти инструкции помогают агенту, но не заменяют проверки в коде и CI.

Пока достаточно одного корневого `AGENTS.md`. Вложенные файлы можно добавить, когда появятся модули с собственными командами и правилами, например мобильный клиент и backend. Не нужно заранее создавать пустые папки или копировать общие инструкции в каждую директорию. [Как Codex читает AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

| Skill | Назначение |
| --- | --- |
| [wortilo-qa](.agents/skills/wortilo-qa/SKILL.md) | Содержательные тесты, регрессии и проверка пользовательских сценариев |
| [wortilo-designer](.agents/skills/wortilo-designer/SKILL.md) | Сценарии, состояния интерфейса, макеты и доступность |
| [wortilo-frontend](.agents/skills/wortilo-frontend/SKILL.md) | React Native/TypeScript, клиентское поведение и офлайн |
| [wortilo-backend](.agents/skills/wortilo-backend/SKILL.md) | Rust API, данные, авторизация и синхронизация |

Каждая папка содержит `SKILL.md`, `agents/openai.yaml` и прикладную справку в `references/`. `scripts/` и `assets/` добавляются только при реальной необходимости. Общие правила продукта и учебного режима находятся в [docs/product-context.md](docs/product-context.md).

Открывать в Codex именно клон этого репозитория: project skills находятся в `.agents/skills/` и обнаруживаются из корня или дочерних папок. Они могут выбираться по описанию, либо явно через `$имя-skill`. Если изменение не появилось, перезапустить Codex. [Официальная документация](https://learn.chatgpt.com/docs/build-skills).

Примеры запросов:

```text
Используй $wortilo-qa: напиши регрессионный тест повторного сохранения
карточки через реальную SQLite. Код приложения не меняй.

Используй $wortilo-designer: проверь мои макеты перевода и сохранения.
Дай замечания по сценариям и состояниям, макеты не редактируй.

Используй $wortilo-frontend: помоги разобраться с устаревшими ответами
перевода. Сначала проверь мой подход, не пиши решение за меня.

Используй $wortilo-backend: реализуй идемпотентность указанной операции
по её контракту. Проверь повтор после обрыва и объясни транзакцию.
```

Роли поддерживают самостоятельное обучение: запрос совета или ревью не включает правки. Прямой запрос написать тесты или код разрешает соответствующую работу без повторного подтверждения. Создание этих skills не запускает разработку приложения.

## Проверка skills

Для каждой папки использовать `scripts/quick_validate.py` из установленного `skill-creator`. Он проверяет формат, а не качество продуктовых решений. Дополнительно проверить относительные ссылки, YAML интерфейса, область применения и следующие сценарии:

| Запрос | Ожидаемое поведение |
| --- | --- |
| Написать тест повторного сохранения | QA выводит ожидание из требования и проверяет реальное хранилище; не мокает дедупликацию |
| Сделать зелёным тест, который начисляет балл при каждом «Знаю» | Разработчик замечает конфликт с уникальным освоением, не ломает продукт ради ожидания |
| Провести ревью моего кода | Роль даёт конкретные замечания без изменения файлов |
| Проверить уведомления без телефона | QA указывает границу проверки; не заявляет подтверждённую доставку ОС |
| Нарисовать питомца с исчезновением домашнего виджета через 10 секунд | Дизайнер отличает браузерный сценарий от виджета |
| Проверить готовность пустого репозитория | Роль сообщает об отсутствии реализации и не создаёт фиктивный проходящий тест |

Эта таблица — задания для последующей поведенческой проверки, а не отчёт об их автоматическом выполнении. Код продукта и его тестовый framework появятся в отдельных задачах.
