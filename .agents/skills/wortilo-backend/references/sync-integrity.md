# Синхронизация и целостность

Это условия для проектирования, а не утверждение, что схема API уже создана. Не выдумывать окончательную стратегию конфликтов, если она не определена актуальной задачей.

## Повторяемая операция

Определи область уникальности operation_id, обычно вместе с владельцем. Повтор того же запроса должен возвращать согласованный результат без повторного эффекта. Повтор ID с другим содержимым не должен молча подтверждать чужую операцию: определи контракт ошибки. Защити от одновременных запросов ограничением БД и транзакцией.

Проверить обрыв после commit до ответа, затем повтор; два конкурентных одинаковых запроса; частичный сбой записи. Проверять число карточек, событий и кредитов, а не только успешный статус.

## Владение и перенос гостя

Клиентский owner_id не доверенный. Ограничивать по авторизованному владельцу чтение, правку, удаление, список, sync и связанные сущности. Проверять доступ к карточке до работы с её вариантами и событиями.

Гостевой перенос может повторяться и прерываться. Запись сопоставления локальных и серверных идентификаторов не должна теряться между попытками. При объединении сохранять значения, пользовательские правки и происхождение. При сомнении в идентичности не уничтожать записи молча.

## Конфликты и удаления

Часы телефона могут быть неверными. Не считать клиентский timestamp универсальным порядком изменений. Определить версию, cursor и обработку конфликтов по контракту. Удаления должны передаваться так, чтобы старый клиент не воскресил запись. Политику очистки удалений согласовать с максимальным периодом офлайна.

## Прогресс

ReviewEvent и MasteryCredit имеют независимую идентичность. Повтор события и повторное «Знаю» не создают кредит заново. Рост общий для языков. Слияние карточек не суммирует два кредита одного освоения; открытая взрослая стадия сохраняется по продуктовому правилу.

## Проверка эксплуатации

База после миграции содержит прежние карточки и связи. Резервная копия полезна только после восстановления и проверки данных/прав. Синтетические данные подходят для проверки инфраструктуры; реальные коллекции не использовать в dev-логах. Бесплатный тариф оценивать вместе с лимитами, сном, сохранностью БД и возможностью восстановления, а не по слову «free».
