# Выбор продуктовых проверок

Это примеры рисков, а не обязательный полный прогон для каждого изменения. Конкретные ожидаемые значения брать из актуального требования. Не выдавать эту таблицу за выполненные тесты.

| Область | Эксперимент и наблюдение | Что нельзя скрыть подменой |
| --- | --- | --- |
| Перевод | Запрос A начат раньше B, завершён позже; виден B. Результат другого блока не запускает новый цикл | Реальный механизм выбора актуального запроса |
| Длина и выражения | Граница 200/201, Unicode и устойчивое выражение; выражение сохраняется целиком | Правила подсчёта и построение карточки |
| Дубли | Двойное нажатие и повтор operation_id оставляют одну запись; другое значение не исчезает | Реальная уникальность и транзакция SQLite |
| Офлайн | Создать, завершить процесс, открыть в авиарежиме, найти и исправить | Хранилище между запусками, а не кеш компонента |
| Пакеты | Прервать загрузку и симулировать нехватку места; прежние слова доступны | Атомарная замена и обработка сбоя записи |
| Грамматика | Проверенный источник подтверждает форму; отсутствие приводит к «Нет данных» | Не считать машинный round trip эталоном |
| Практика | Три успеха в один день отличаются от успехов в разные дни; «Знаю» требует действия | Правила дат; время задаётся управляемыми часами |
| Рост | 99/100, повтор отметки, слияние дублей и повтор операции | Уникальный кредит в реальном хранилище |
| Напоминания | Отказ, ночь, смена зоны, удаление слова и открытие устаревшего уведомления | Проверки на устройстве; unit-тест не доказывает доставку ОС |
| Виджет | Снимок старой версии и удалённая карточка; переход безопасен | Реальная отдельная поверхность, проверяемая на каждой ОС |
| Расширение | Нет взаимодействия 10 секунд — нет ReviewEvent; нажатие отменяет скрытие; одна активная вкладка | Механизм межвкладочного выбора, разрешения и таймер |
| Аккаунты | Пользователь B запрашивает ID карточки A через чтение, правку, удаление и sync | Серверная авторизация и реальная выборка данных |
| Sync | Обрыв после записи до ответа, повтор той же операции, офлайн-удаление и поздний обмен | Идемпотентность, удаления и транзакции PostgreSQL |
| Миграции | Обновить заполненную БД, а не только создать чистую | Сохранность пользовательских правок и контекста |
| Доступность | Крупный шрифт, screen reader, тёмная тема, звук отдельно от переворота | Реальный фокус, подписи и доступ к действиям |

## Контроль качества самого теста

Назови правдоподобный дефект, от которого защищает assertion. Например, «повтор операции создал второй кредит» проверяется количеством уникальных кредитов и итоговым ростом, а не числом вызовов mock. Для SQL rollback проверь отсутствие частично записанных сущностей. Для API ошибки проверь статус и отсутствие недопустимого изменения в БД.

Создавай независимые записи для разных пользователей и смыслов слова. Каждый тест очищает только свои данные. Не использовать production, личные тексты или live платный API. Flaky-проверку сначала диагностировать; повтор запуска не заменяет исправление гонки.
