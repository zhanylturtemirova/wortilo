# Инварианты клиента

## Перевод и словарь

Каждый ввод имеет версию запроса и язык источника. Результат старой версии не меняет новый ввод; целевые языки завершаются независимо. Программное заполнение не инициирует перевод обратно. Различай машинный результат, словарные сведения и ручные правки; источник и отсутствие поля не теряются при отображении.

## Локальные данные

Пользовательские записи отделены от заменяемых пакетов. Сохранение карточки и её вариантов атомарно. Стабильный ID не вычисляется только из текста. Повтор операции не создаёт новую сущность, а похожее написание не доказывает тождество значения. Обновление приложения проверяется на заполненной БД.

UI может показывать ожидающее изменение, только если ошибка позволяет восстановить понятное состояние. Не сообщай окончательное сохранение до успешной локальной записи. Для офлайна чтение не зависит от сети или будущей авторизации.

## Практика и системные возможности

События повторения и ручное освоение — отдельные действия. Один и тот же event_id не изменяет прогресс дважды. Управляемые часы облегчают тесты; реальные часовые пояса и ограничения ОС всё равно проверяются отдельно.

Отзыв разрешений и отсутствие голоса — рабочие состояния. После удаления слова отменить связанное планирование; при открытии старого уведомления проверить актуальное наличие карточки.

## Виджет и расширение

Нативный виджет получает небольшой атомарный снимок с версией; не держит React Native постоянно работающим. Из снимка исключены ключи и токены. Тап проверяет актуальную карточку.

Расширение имеет собственное хранилище и синхронизацию, а не прямой доступ к мобильной SQLite. Разрешения нужны для появления, не для сбора текста страниц. При выходе из аккаунта убрать его кеш и токены. Браузерный таймер и мобильные уведомления не используют неявно одни настройки.
